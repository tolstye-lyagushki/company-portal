# Такояки — портал команды (демонстрационная версия)

Демонстрационный портал сотрудников кафе «Такояки» и «Такояки-мисэ» (Санкт-Петербург): база знаний, задачи,
заявки и сотрудники. Интерфейс на русском языке, работает на компьютере, планшете и телефоне.

## Важно: это демонстрация

- **Данные хранятся только в вашем браузере** (`localStorage`). Они не отправляются на сервер и не синхронизируются
  между пользователями, устройствами и браузерами: каждый, кто открывает портал, видит свою копию демо-данных.
- **Роли и права доступа не защищают данные.** Переключение пользователя и ролей нужно только для показа интерфейса:
  входа по паролю нет, а проверки выполняются в браузере и легко обходятся.
- **Не вводите реальные персональные, кадровые и конфиденциальные данные.** Все сотрудники, адреса и телефоны в
  демо-наборе вымышлены: почта в зарезервированном домене `example.com`, телефоны с несуществующим кодом `000`.

## Возможности

- **Главная** — приветствие, быстрые действия, сводка, мои задачи, последние заявки и статьи.
- **База знаний** — создание, редактирование и удаление статей, категории, поиск по заголовку и тексту,
  форматирование текста и вставка изображений.
- **Задачи** — ответственный, срок, приоритет, статусы «Новая», «В работе», «На проверке», «Выполнена»,
  фильтры, вид списком и доской, комментарии.
- **Заявки** — категории, статусы «Новая», «Рассматривается», «Одобрена», «Отклонена», «Выполнена»,
  комментарии и история изменений; сотрудник видит только свои заявки.
- **Сотрудники** — список с поиском и фильтрами, профиль сотрудника.
- **Администрирование** — сотрудники, должности, роли и права доступа, категории базы знаний, журнал действий.

## Роли и права

Роль задаёт права по умолчанию; администратор может дополнить или урезать их для должности и для отдельного
сотрудника (индивидуальная настройка важнее должности, должность — важнее роли).

| Роль | По умолчанию |
| --- | --- |
| Сотрудник | Читает опубликованные статьи, создаёт свои заявки, видит справочник сотрудников. Задачника нет. |
| Редактор базы знаний | Плюс создание, редактирование и публикация статей, просмотр черновиков. |
| Руководитель | Плюс задачник (все задачи, создание, правка, назначение, статусы) и решения по всем заявкам. Без админ-панели. |
| Администратор | Все права. |

Доступ к задачнику настраивается отдельно: доступ, просмотр всех задач или только своих, создание, редактирование,
назначение исполнителей, смена статуса, удаление. Нельзя менять собственные роль и права, выдавать права, которых
нет у себя, и управлять администраторами без роли администратора. Переключение демо-пользователя и сброс
демо-данных доступны всем — это управление демонстрацией, а не вход в систему.
- **Общее** — поиск по порталу, уведомления, переключение демо-пользователя (меню в правом верхнем углу),
  сброс демо-данных (меню пользователя → «Сбросить демо-данные»).

## Запуск на своём компьютере

Нужен [Node.js](https://nodejs.org/) версии 22.12 или новее.

```bash
npm ci
npm run dev
```

Портал откроется по адресу http://127.0.0.1:5180. На Windows можно просто дважды щёлкнуть `Запустить.cmd`.

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Запуск для разработки с автообновлением |
| `npm run build` | Проверка типов и сборка готового сайта в папку `dist/` |
| `npm run preview` | Просмотр собранного сайта на http://127.0.0.1:5181 |
| `npm test` | Тесты модели прав и миграции данных |

## Публикация на GitHub Pages

В проекте уже есть настройка автоматической публикации `.github/workflows/deploy-pages.yml`: при каждой отправке
в ветку `main` GitHub сам собирает сайт и выкладывает папку `dist`.

> **Публичный репозиторий делает весь исходный код и историю коммитов доступными всем в интернете.**

1. Создайте на GitHub пустой публичный репозиторий `company-portal` (без README и лицензии).
2. В репозитории откройте **Settings → Pages** и в поле **Source** выберите **GitHub Actions**.
3. Отправьте код:
   ```bash
   git remote add origin https://github.com/ВАШ_ЛОГИН/company-portal.git
   git push -u origin main
   ```
4. Ход сборки виден на вкладке **Actions**. Через 1–2 минуты сайт откроется по адресу
   `https://ВАШ_ЛОГИН.github.io/company-portal/`.

Сайт можно разместить по любому пути: пути к файлам относительные (`base: './'` в `vite.config.ts`), а адреса
страниц строятся через `#`, поэтому сервер настраивать не нужно.

## Устройство проекта

Vite, React, TypeScript, React Router, редактор TipTap, DOMPurify (очистка HTML статей), иконки lucide-react,
шрифты Unbounded и Manrope (собираются вместе с сайтом, внешние серверы не используются).

```
src/
  main.tsx              маршруты и закрытие разделов без прав
  store.tsx             данные, сохранение в браузере, действия с проверкой прав, журнал
  styles.css            дизайн-система «Такояки»: цвета, шрифты, компоненты, адаптивность
  lib/permissions.ts    роли, права, единая проверка доступа
  lib/migrate.ts        перевод ранее сохранённых данных в текущий формат
  data/seed.ts          демонстрационный набор данных
  components/           меню и шапка, фирменная графика, общие элементы, редактор прав
  pages/                разделы портала
tests/                  тесты прав и миграции (npm test)
```

## Чего не хватает для настоящей работы

Система ролей в этой версии работает только в браузере: пользователь, который изменит код страницы или содержимое
localStorage, может её обойти. Для настоящей защиты нужны сервер с базой данных, вход по паролю или через
корпоративный каталог, проверка каждого права на сервере, хранилище файлов, синхронизация между пользователями
и HTTPS, а при работе с реальными данными сотрудников — соблюдение требований 152-ФЗ.
